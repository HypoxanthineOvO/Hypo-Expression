# 结构与要求

## 一个入口，三套操作

总入口先加载核心原则，再根据任务选择沟通、写作或改稿。操作文件分别规定身份、工作过程和交付方式，可以组合使用。例如写论文时执行写作与项目查阅，向作者交付时执行沟通要求。

| 层级 | 内容 |
|---|---|
| 总入口 | 识别任务、按需读取文件 |
| 核心原则 | 虚构反对观点、防御性表达、作者身份、自然搭配、信息与格式、查证等八条 |
| 操作 | 沟通、写作、改稿 |
| 语言层 | 词语、句子、段落和篇章层面的常见问题，以及判断是否用错的方法 |
| 文体 | 四个大类及其细分文体 |
| 查证 | 查阅资料、纠错补充、把未解决的问题交给作者 |

## 语言层

多数带AI味的写法本身合乎语法，人也会用。问题在于它们出现在不合适的位置、替代了本该写出的具体内容，或者密集到让读者注意到写法本身。语言层因此不列禁用词表，而是对每类写法说明用错时的样子和改法，并给出判断三问：它在这里承载了什么，是否符合当前文体的惯例，同类写法是否过密。

## 文体树

文体按作者与读者的关系分为四类：

| 大类 | 细分文体 |
|---|---|
| 报道：以事实为主，作者不出场 | 时效消息、活动报道 |
| 论述：作者有立场或以解释为目的 | 观点、口述成文、介绍与文案、科普与教程（在大类文件中分节） |
| 说明与汇报：帮助读者理解、判断或执行 | 报告（在大类文件中）、仓库文档、界面文案 |
| 学术 | 论文 |

大类文件写该类文本的共同要求，细分文体只写特有的惯例。新的用途先归入最接近的大类；只有当它有大类没有覆盖、并且会影响成稿的惯例时，才增加细分文体。这样文体增加时，规则不会变成按用途平铺的长列表。

个人栏目的固定格式（例如某个新闻栏目的首句加粗）放在使用者自己的项目规范中，Skill 只保留可以推广到同类文本的要求。

## 查证与表达

润色可能需要额外信息。模型应在允许访问的资料中主动查找前后文、定义、事实和已有决定，纠正有依据的错误，补足理解所需背景。查阅后仍有实质冲突或作者取舍时，再提出具体问题。

查证与展示分别处理：数据有来源，不等于正文必须写入所有路径和内部标签；正文省略这些标签，事实仍需有依据。

## 信息与格式

默认保留已有文本的事实、数字、条件、例子、论证作用及有用格式。用户明确排除的内部检查或自证可以整体删除，删除范围只限于该类内容。正式程度、字数和是否分点不单独决定文本质量。

## 判例

判例放在它所说明的规则旁边：搭配和句式的判例在语言层，文体相关的判例在对应文体文件。每条判例写出问题原句、更好的写法和原因，说明的是具体语境下的处理方向，不作逐词替换表。
