# 结构与要求

## 一个入口，三套操作

总入口先加载十条共同原则，再根据任务选择沟通、写作或改稿。操作文件分别规定身份、工作过程和交付方式；它们可以组合使用。例如写论文时执行写作与项目查阅，向作者交付时执行沟通要求。

| 层级 | 内容 |
|---|---|
| 总入口 | 识别任务、按需读取文件 |
| 共用原则 | 防御性表达、假靶子、自然搭配、作者身份、信息与格式等 |
| 操作 | 沟通、写作、改稿 |
| 方法 | 内容与结构、查证与作者裁决 |
| 文体 | 报告、新闻、文章、论文 |
| 判例 | 搭配与语气、身份与呈现、信息与科研 |

## 三类写作

报告围绕要解决的问题呈现结果、依据和分析，可以提出有依据的建议。新闻以事件为中心，区分事实、来源说法和推测。观点文章保留作者立场，允许模型根据口述观点主动补充背景、例子、解释和推理。科普和教程按其解释目的处理。

文章的作者声音不等于每句都用“我”，客观报道也不等于罗列所有观点。具体判断取决于作者、读者和用途。

## 查证与表达

润色可能需要额外信息。模型应在允许访问的资料中主动查找前后文、定义、事实和已有决定，纠正有依据的错误，补足理解所需背景。查阅后仍有实质冲突或作者取舍时，再提出具体问题。

查证与展示分别处理：数据有来源不等于正文必须塞入所有路径和内部标签；正文省略这些标签也不等于事实无需依据。

## 信息与格式

默认保留已有文本的事实、数字、条件、例子、论证作用及有用格式。用户明确排除的内部检查或自证可以整体删除；删除范围不扩展到其他技术信息。正式程度、字数和是否分点不单独决定文本质量。

## 示例如何使用

判例说明具体语境下的问题及处理方向，不提供统一的逐词替换表。反馈应记录用户否定了什么、认可了什么、适用于哪种文本。原文、改稿和历史后续稿分别保存，后期稿不自动成为标准答案。
