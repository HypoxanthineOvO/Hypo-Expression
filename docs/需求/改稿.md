# 改稿

## 现在

模型先理解原文要表达什么、属于什么文体、这次允许改到什么程度，再处理具体表达问题。默认保留数字、机制、原因、条件、例子、编号、加粗和分节；用户没有要求缩短，就不把润色做成摘要。原文已经合适的段落保留。遇到指代不清、数据冲突或依赖前后文的地方，先查当前稿、上下文和历史决定，再把需要作者取舍的问题带到对话里。

## 规则

- 默认保留信息量与原有组织形式。只有明确要求缩短时才压缩，只有明确要求切换格式时才调整表达形式。
- 用户明确排除的核验记录整块删除，不只换标签；删除范围只限这一类内容，其他段落照常改好。
- 区分局部润色、结构调整、重写和缩写，按授权的幅度处理。用户对原稿基本满意、只想修瑕疵，与对原稿不满意、要求重写，修改幅度不同。
- 原文是理解作者意图的起点，不是全部事实来源。指代不清、术语含义不明、数据冲突、因果缺环时，查当前稿、上下文、结果和其他可靠来源。
- 保留承担论证作用的句子：交代研究目的、承接上一结果、引出下一步调查的句子，看似过渡，实际是论证的一部分。
- 正式语体可以保持正式，不自动改成口语。润色不等于缩写，也不等于把正式文本改成日常聊天。
- 用户评估效果时，提供完整原文与改稿对照，按完整段落或小节并排，保持顺序和足够上下文。只列几个词的变化，无法判断效果。
- 用户授权结构调整时，按写作的组织方法重排；普通润色不扩大为整篇重组。

## 不能坏

- **不丢原因和条件。** 新闻改稿丢掉了高端算力资源、折扣周期，以及评论区给出的并发上限 1000 和客户调整方式后的资源解释，被用户评为“过于精简”。原帖给出的原因要留在相应事实旁边。
- **不压平编号和加粗。** 课程请假要求被改成一整段长文，编号步骤和重点加粗都没了。正确做法是先按编号列出老师给出的请假步骤，再单列与请假方式无关的注意事项，例如请假超过 20 条会核查并联系老师、请假后的出勤计分需要读者确认。
- **不改变判断强度，不删论证句。** 论文改稿删掉 “The latter result directs the investigation beyond copy-group waiting.”，下一段的票号机制就失去了由来；把 suppressing 改成 eliminating、exercise 改成 confirm，断言被加强；“separates their effects” 弱化成 “evaluate each revision”，分别评估两项修改贡献的目的也没有保住。
- **不把内部检查换个名字留下。** CPU 报告把“已核验”改成“核验结果”，文件身份、计算区间这些检查记录仍留在正文。用户要求把这一整块删掉，并改好其他段落。
- **不擅自缩短或改格式。** 用户没有要求缩短，就不能把润色做成摘要；没有要求换格式，就不能把编号、表格和分节改成连贯段落。
- **不把内部纪律写成给读者的提醒。** “不能擅自保证不扣分”是模型给自己的约束；读者需要的是“老师没有说明请假后出勤分如何计算，请自行确认”。

## 牵连

- 改稿执行表达原则，读语言层和文本所属的文体。
- 用户授权结构调整时，组织方法来自写作；改稿的交付说明按沟通要求写。
- 修改论文或项目文档时，查证范围按项目资料确定，不把样本测试的封闭材料范围套到真实项目。
