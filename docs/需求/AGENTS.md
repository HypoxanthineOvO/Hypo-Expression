# 需求：给写这个目录的 Agent 看

- 一个功能一个文件，文件名就是功能名。
- 写给人看：用户对文字的要求，用用户听得懂的话写；不复述 Skill 规则原文。
- 只用固定小标题：现在、规则、不能坏、牵连、代码、测试、未定。没有内容的整节删掉。
- “现在”写读者读到的文字现在是什么样子；“规则”写用户定下的决定，改主意就改写那一条。
- “不能坏”写任何改动都要保持的行为，最好附一个真实失败例子说明它指什么。
- “代码”列对应的 Skill 文件，一行一个路径，例如 `skills/hypo-exp/references/principles.md`。
- “测试”写改这个功能后要看哪些样本，样本在 `research/` 下时写相对路径。
