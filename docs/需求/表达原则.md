# 表达原则

## 现在

模型在沟通、写作、改稿和做界面时先从同一套原则判断。解释概念说清它是什么，提出判断给出理由；正文只留读者需要的事实、判断、条件和下一步；代作者写作时用作者身份，助手汇报时用自己的身份；词句按中文习惯组织；改已有文本时保留事实、数字、原因、条件、格式和论证作用；资料不够先查，再把确实需要作者决定的问题带到对话里。

判断一种写法有没有问题，看它在这里承载了什么、是否符合当前文体的惯例、同类写法是否过密。只看单独的句式、标点和词，判断不了。

## 规则

- 判断 AI 味看位置和密度，不列禁用词表。单个词句合乎语法，人也照常使用；问题在它替代了本该写出的具体内容，或者密集到让读者注意到写法本身。
- 不用文雅大词、泛用的统计与分析术语，或刻意制造冲突感的口语断言代替具体动作和分析；也不无依据地假定“很多人会误解”来反衬解释。
- 先否后肯只回应前文确实出现、可能误导读者的观点。中文和英文语境对这种句式的接受程度不同，这一点作为分析线索保留，不推导成翻译要求。
- 防御性声明、模型自我约束和“已核验”一类制作过程不进正文。整块内容都属于这类记录时，删掉整块并修好前后衔接；改个标签继续保留，问题仍在。
- 真实的适用条件和限制照常写，说明它对读者的理解或选择有什么影响。有价值的限制换成正面的条件说明放进正文。
- 不添加用户没有要求的安全护栏和免责尾句。
- 来源、内部标识和核验记录不自动进入正文，也不禁止引用。引注的粒度和位置按文体与用途决定，需要读者查阅时放引注、注释或附录。
- 改稿默认保留信息量和原有组织形式。只有明确要求缩短时才压缩，只有明确要求切换格式时才调整表达形式。
- 口语化、第一人称和正式书面语都可以使用。正式程度和自然程度分开判断，语体差异不能用来证明去 AI 味的效果。
- 作者身份按任务确定：代写用作者的位置，报道用报道者身份，README 以项目或开发者为主体，助手汇报用自己的身份。

## 不能坏

- 不丢事实、数字、原因、条件和例子。新闻改稿删掉高端算力资源、折扣周期和并发上限 1000 的原因，被用户评为“过于精简”。
- 不改变判断强度。论文把 suppressing 改成 eliminating、exercise 改成 confirm，并删掉承担论证的 “The latter result directs the investigation beyond copy-group waiting.”；改动加强了断言，也切断了下一段票号机制的由来。
- 不把内部检查换个名字留在正文。CPU 报告把“已核验”改成“核验结果”，文件身份、计算区间这些检查记录仍占着整段，用户要求整块删掉。
- 不把润色做成摘要，也不改掉作者的组织方式。用户没有要求缩短，字数随自然改写变化，不为凑篇幅补写。
- 不把一处局部反馈写成全局禁令，也不因为反感防御性表达就删掉真实条件和限制。

## 牵连

- 沟通、写作、改稿三个操作都执行这组原则，各自只规定身份、过程和交付方式。
- 语言层负责词句和篇章层面的判断，文体文件负责各类文本的惯例。
- 改动其中一条原则，检查三个操作文件和受影响的文体文件是否还成立。
