# 写作

## 现在

模型从资料、事实、提纲或口述观点起草文章、报告、新闻和文档。先确定作者、读者和用途，再决定正文放什么、细节放在哪里。读者需要先知道的结果或问题尽早出现，依据和机制随后展开；每段承担具体作用，段落之间写出实际关系。内部执行记录、调试信息和写作过程不进入成稿。

## 规则

- 先明确文档要回答的核心问题，开头让读者理解任务和它的意义。核心结论、方法或建议放在显眼位置，组件和细节按支撑关系展开。
- 数据和例子对应要说明的判断，写清它们证明或说明了什么，不只列执行了哪些测试。
- 每段、每节有明确作用，前后的问题、方法、证据和结论互相呼应。
- 结果直接交代主要发现和比较含义，不让读者从数字里自行猜测重点。
- 正文的信息取舍以读者任务为准。模型研究时需要的数据出处、来源代号、核验记录和细节，不自动成为正文必需内容；引注的粒度和位置按文体与用途决定。
- 口述成文先理解核心主张、已有理由、重点和语气，再主动查找背景、事实和可核实的案例，补出从事实到判断的解释。普通的背景、例子和衔接不必逐项请示；会改变主旨、引入新的价值判断或把立场推得更远的新论点，交给作者决定。
- 需要作者决定的问题在对话里提出，模型没弄清的事情不写成正文里的“无法确定”。
- 新闻区分正式发布、转述、预告、体验和讨论，保持相应的事实归属。原因分析来自评论区时，写成评论区的看法。
- 活动报道先按海报核对时间、地点、题目、主讲人和主持人，修正转写稿中的人名、作品名和引文，再按讲座层次转述。称谓、栏目格式和署名沿用发布方的往期报道。
- 报告允许明确判断，事实、推断和建议的关系写清楚。内部检查记录按报告目的取舍，面向审查或复核时保留详细来源。
- 用户口述观点时，保留作者明确的态度、侧重点和判断强度。明确的判断直接说，试探性的想法保持开放程度。

## 不能坏

- 不编造事实、个人经历和实测结果。自拟情境简明标注性质，不写成真实经历。
- 不把内部执行记录、开发条件和调试信息写进成稿。用户要的是结果和分析，不是“已核验”“运行完整”之类的制作过程。
- 不把来源标签和内部代号塞满正文。用户要求报告写详细时，指的是仿真设计、对比和方法，同时明确排除“增强文献引用”和“增加防御性标记”。
- 不把完成的工作介绍成未完成品。介绍一套已经整理好的规则，就写它是什么、解决什么问题；开头写“目前仍是实验草案，后续还需完善”，会把完成的工作介绍成半成品。
- 不把模型的信息缺口写进正文。查过资料仍要作者决定的问题，在对话里提出。
- 不擅自加强或削弱作者的立场，也不替作者补出他没有提出的反方观点。

## 牵连

- 写作与改稿共用表达原则、语言层和文体细则；交付说明按沟通要求写。
- 写作中的信息取舍和结构要求，同样是改稿授权结构调整时的依据。
