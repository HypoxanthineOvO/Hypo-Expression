# Hypo-Expression

[![Version v1.3.0](https://img.shields.io/badge/version-v1.3.0-blue)](https://github.com/HypoxanthineOvO/Hypo-Expression/releases/tag/v1.3.0) [![License MIT](https://img.shields.io/badge/license-MIT-green)](LICENSE)

Hypo-Expression（短名 `hypo-exp`）是一个给 AI 读的中文表达规范 Skill。它让模型在沟通、写作和改稿时，写出没有 AI 味、符合作者身份和文体惯例的中文。

**你有没有在使用 AI 的过程中遇到这些情况？**

- **它先反驳一个你根本没提出的观点。** 你让它“把这段话说清楚”，它却开始解释：“把话说清楚，并不是把所有专业术语都改成大白话，而是在保留专业性的同时提高可读性。”你只是想改段文字，读完却觉得它在把你当傻子。
- **它在报告里堆满检查记录，却没讲你关心的内容。** 你想看结果和分析，迎面而来的是“已核验”“SHA-256 一致”“运行完整”“输出一致”。翻了半天，报告的核心内容反而没几句。
- **它把整理要求写成了一连串“不能声称”。** 你让它整理老师的课程要求，它回复“不能声称已覆盖全部要求”“不能擅自保证请假后不扣分”。正经要求没看到几条，“不能声称”倒是一屏，眼睛先受到了攻击。

Hypo-Expression 整理了这些具体问题背后的几类判断：

- **直接说明内容。** 解释实际信息，只回应确实存在的误解。
- **在对话中完成回答。** 先交代结论、理由和必要例子，让读者当场理解结果；文件承载详细内容。
- **把读者需要的内容放在正文里。** 写结果、依据和具体提醒，自我辩护和制作过程留在正文之外。
- **使用自然的中文，保留作者立场。** 词语组合符合表达习惯，文章体现作者本来的意思。
- **保留有用的信息和格式。** 润色不等于缩写，数字、条件、论证衔接、编号和加粗都各有作用。
- **信息不足时主动查阅。** 先读相关材料，再把确实需要作者决定的问题拿来讨论。

这些判断针对的是写法用错了地方，而不是某些词句本身。“为……提供了参照与启发”放在校园讲座报道的结尾，是审稿老师也会保留的惯例；放在技术文章每一段的末尾，就成了没有内容的空话。所以 Hypo-Expression 不列禁用词表，而是说明每类写法在什么情况下算用错、该怎么改。判断一种写法时看三点：它在这里承载了什么，是否符合当前文体的惯例，同类写法是否过密。

## 三种用法

日常使用 AI 时，**让它与自己沟通、让它起草内容、让它修改已有文本**，是三种不同的需求。Hypo-Expression 针对各自的作者身份、处理过程和交付方式，分别整理了操作要求，共用同一套表达原则。

安装后，直接向 AI 说明任务：

| 功能 | 示例请求 | 处理重点 |
|---|---|---|
| 沟通 | 使用 Hypo-Expression，从现在开始按这套规范和我交流 | 直接回答问题，解释结果与实际影响，提供必要例子，不用附件代替回答 |
| 写作 | 使用 Hypo-Expression，把这些观点写成文章 | 理解作者立场，补充必要的事实、背景、例子和推理，组织成文 |
| 改稿 | 使用 Hypo-Expression，润色这份报告 | 处理表达与衔接，默认保留信息和有用格式，必要时查阅背景 |

Skill 短名是 **`hypo-exp`**，也可以直接说“用 hypo-exp 帮我写一份报告”。[使用说明](docs/使用.md)提供报告、新闻、活动报道、口述文章、论文和仓库文档的具体用法。

## 文体

写作和改稿按文本类型选用细则。文体按作者与读者的关系分为四个大类：大类文件写这类文本的共同要求，细分文体只补充自己特有的惯例。

| 大类 | 作者与读者的关系 | 包括 |
|---|---|---|
| 报道 | 以事实为主，作者不出场 | 时效消息；活动报道（讲座、会议、课程活动） |
| 论述 | 作者有立场，或以解释为目的 | 观点文章、口述成文、介绍与文案、科普与教程 |
| 说明与汇报 | 帮助读者理解、判断或执行 | 报告；仓库文档；界面 |
| 学术 | 遵循领域的研究叙述 | 论文 |

遇到新的用途，先归入最接近的大类；只有当它有大类没有覆盖、又会影响成稿的惯例时，才增加一个细分文体。[设计](docs/设计.md)说明了分类方式和规则组织。

## 安装

从 [v1.3.0 Release](https://github.com/HypoxanthineOvO/Hypo-Expression/releases/tag/v1.3.0) 下载 `hypo-exp-1.3.0.zip`，解压得到 `hypo-exp/`。保留完整目录，入口引用的操作和参考文件也是 Skill 的组成部分。

### Codex

将 `hypo-exp/` 放到用户级 `~/.agents/skills/`，或项目内的 `.agents/skills/`。也可以克隆仓库后建立软链接：

```sh
git clone https://github.com/HypoxanthineOvO/Hypo-Expression.git
mkdir -p ~/.agents/skills
ln -s "$(pwd)/Hypo-Expression/skills/hypo-exp" ~/.agents/skills/hypo-exp
```

软链接安装后，客户端直接读取仓库中的 Skill，更新仓库即可使用新内容。已有独立副本时，先把它移到技能目录之外备份，再建立同名链接。从 1.0.x 升级时请替换整个目录：1.1.0 调整了参考文件的位置，旧文件留在目录里会和新规则同时被读到。目录约定见 [Codex 官方 Skill 文档](https://learn.chatgpt.com/docs/build-skills)。

### 其他 AI

支持 Agent Skills 的客户端，将目录放到其规定的技能目录。有文件读取能力的 AI，可以从包内 [`SKILL.md`](skills/hypo-exp/SKILL.md) 开始，按指引读取相关文件。仅支持附件的客户端，需要能够解压文件包并读取 Markdown 附件。

## 实验与评测

Skill 的效果由作者对照原文和生成结果评价，模型不给自己打分。已经做过的实验覆盖八组真实文本的改稿、沟通与写作入口、README 三种写法对照，以及四个网页原稿和几个真实页面的试修。固定样本用于回归测试，不能当作未见样本的泛化结果。

评测方法、实验条件和各自结论见[评测](docs/评测.md)。欢迎在 Issue 中提供可公开的输入、输出、使用模型及修改意见。
