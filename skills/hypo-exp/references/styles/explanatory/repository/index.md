# 仓库文档

适用于README、版本说明、提交信息和仓库配套文档。先理解仓库实际提供什么、读者是谁、这份文档要帮助读者完成什么，再选择内容与组织方式。仓库可以承载不同种类的内容，不预设它一定是可安装的软件产品，也不把某类仓库的栏目固定成通用模板。

## 共同要求

- **介绍对象本身。** 让读者理解仓库内容、用途及重要关系，不只罗列目录、模块名或工作步骤。背景、动机、价值和使用条件按需要展开。
- **围绕文档用途安排重点。** 面向首次接触的读者、正在使用的人和维护者时，各自需要的信息不同。按重要性选择开头和展开顺序，不照搬资料或提交的时间顺序。
- **把抽象描述落实为内容。** 出现能力、改进或用途时，解释具体能做什么或发生了什么变化。资料不足时查阅，不凭文档类型编造功能、数据、效果或使用场景。
- **保留理解和使用所需的信息。** 篇幅由内容决定。解释复杂内容可以展开，短小变更无需套入长模板；不以字数、标题数或条目数作为质量标准。
- **采用合适的叙述身份。** README默认以仓库内容或开发者为主体，不用第一人称“我”。确有团队时可称团队，不能虚构多人组织；作者明确要求个人叙述时遵循其要求。
- **让事实和状态有实际用途。** 适用条件、依赖、已知问题、测试范围在影响读者理解或使用时具体交代，不用连续的未做事项或自证替代介绍。文档中的断言应与所读材料及对应版本一致。
- **格式服务阅读。** 保留或选择有用的标题、列表、表格、链接与图示。版本、许可证等标记应指向真实信息，不添加未经依据支持的状态徽章。
- **贡献署名准确。** 按实际贡献及维护者意愿署名。AI协助可注明工具及工作内容，不虚构账号、人类身份或未发生的贡献。

## 按文档用途读取

| 文档 | 细则 |
|---|---|
| README与首页介绍 | [README](readme.md) |
| Release、Changelog与Commit message | [变更说明](changes.md) |
| 教程、操作指南、设计说明与参考资料 | [配套文档](supporting-docs.md) |

这些细则同时适用于写作和改稿。局部润色尊重原文范围，明确要求重写时可以重新组织与补充内容。
