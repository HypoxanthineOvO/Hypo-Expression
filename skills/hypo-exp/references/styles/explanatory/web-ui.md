# 界面文案与网页表达

适用于做或改网页、应用和工具界面：用户能看到的文字（按钮、标签、占位符、提示、确认、空状态、角标、状态栏），以及承担表达作用的布局、层次、对齐和配色。界面是产品内容，不是开发过程的注脚；网页正文同时遵守共用原则。

## 判断标准

页面按稳定的使用者视角和总体内容逻辑组织，视觉表达符合内容关系和使用习惯。下面的小字、卡片、图标、对齐和配色要求，都是这两条在具体场景的应用。

次要标签、说明文字和小字默认不加，让分组、位置和层级说明关系。只有用户明确要求展示、并且用途明确时才加；模型认为“有用”不是添加理由。资料缺口和计算口径交给开发者，不写进界面。

界面上每一句不是数据本身的话，都先回答：删掉它，用户会失去什么。答不上来的就删掉。用户要完成的是手头的事，不是了解系统如何约束自己。删的是多余的说明，不是有效信息：关键数据的可见性、位置和作用都要保留，不压成小字或一句空卡。

## 组织页面

- 先明确内容对象、它们之间的关系和用户要做的操作，再选列表、卡片、表格、时间轴等表达。本应独立的单元不合并成一张卡，同级的单元不一部分展开、一部分合并；整理时也不采用“全部删掉”的统一策略。
- 按产品使用者的需要组织，不按开发阶段、存储路径或源码分组组织。开发条件、Mock 与静态示例说明、接入进度、内部标签不进入界面，也不换成“已删除”之类的公告。
- 同类项一起处理：同类指标一起放在相应位置，或都不放，不擅自只突出其中一个。
- 主页面、详情、编辑、返回和反馈共同构成使用过程。页面看起来齐整，不能代替操作是否完整。
- 需求未知时，先用已有资料确定任务和展示需要；会改变整体设计的分歧集中询问，其余直接推进。

## 视觉

- 保留已认可的整体框架、结构、配色和风格。局部修复不自动获得重排结构、更换色系或视觉语言的授权；换色本身不是改善。
- 对齐按语义关系确定共同基线、列轨道、间距和容器关系，并在实际页面里查看。元素框顶部相同、页面没有横向溢出、控件能点，只说明程序跑通，不说明主次和观感合格。
- 文件格式由合适的图标承担识别，不靠大块文字标签；图标只帮助识别，不替代标题、分类和信息组织。
- “干净”不等于寡淡。动效、玻璃、图像和鲜明色彩都可以保留，前提是结构清楚、颜色有语义、表现一致。

## 常见问题与解法

**自我说明进入界面。** 界面解释自己没做什么、不冒称什么、为什么这样设计，例如声明某功能未启用、某数据不保证准确、某操作不影响其他数据。这类话面向的是实现者的责任边界，不是读者的下一步。解法：功能边界写进文档；只有当用户即将依赖一个实际不存在的能力时，才在该操作的旁边用一句陈述说明它现在做什么，不解释它不做什么。

**无事件时的平安播报。** 没有修改时显示"无修改"、连接正常时显示"已连接"、没有草稿时显示"无草稿"。界面把"没出事"当成需要占版面的信息。解法：无状态即无文字；状态文字只在异常、进行中或需要用户行动时出现。

**教学式提示常驻版面。** 快捷键对照、操作步骤、格式说明、浏览顺序作为正文长期挂在页面上。解法：操作说明放进 tooltip、aria 描述或首次引导；格式约束在出错时再说，不提前布防。

**确认弹窗写成小作文。** 一次确认里解释操作影响的所有边界、列举不受影响的数据、预告之后的补救入口。解法：确认框只回答两个问题——会发生什么、能不能撤销；撤销能力用撤销按钮本身证明，不在确认文案里预告。

**占位符冒充标签或正文。** 输入框占位符承担字段名称、可选性说明和示例三重职责，或者把说明文字伪装成已填写的内容。解法：字段有可见的名字或从上下文自足；占位符只给最短格式示例，不写使用说明。

**精度与计数噪音。** 状态时间精确到秒、完成度写成内部分数、来源或版本号直接贴在条目上。解法：按读者的决策需要截断精度；内部标识留在日志、导出口和调试入口。

**一个状态堆叠多种信号。** 同一状态同时用颜色块、图标、文字徽章、删除线表达，或把语义不同的状态涂成难以区分的同一种样式。解法：一种状态一个主信号，其余信息收进详情和无障碍描述；语义不同的状态在视觉上必须可区分。

**同一对象的多个入口行为不一致。** 标题、手柄、右键、快捷键指向同一批操作却各有不同的触发结果，用户无法预测点击后果。解法：每个对象一个主入口承担最常见动作，其余入口只做等价的快捷方式；保留多个入口时，同名动作的行为必须相同。

**提交时机分裂。** 同一个编辑区域里，有的字段改了立即生效，有的字段要再点一次"应用"，有的要按回车，用户没有理由猜到差别。解法：一个编辑面只存在一种提交模型——要么全部自动提交，要么全部显式提交；选择自动提交时，校验失败就地标错，不静默丢弃。

**操作入口依赖隐藏。** 拖动把手、删除按钮只在悬停时出现，且没有常显的等效路径；主要动作的发现依赖偶然悬停。解法：常显低对比度的入口，悬停时加强；触控与桌面一致。

**交互反馈与状态语义撞色。** 悬停底色和某个业务状态底色使用同一个颜色，鼠标划过时正常条目看起来像已结束条目。解法：交互反馈色与状态色分别取值，任何时候两者不同时出现在同一区域造成误读。

**装饰性层次过多。** 卡片套卡片、每个分区再带边框阴影，弹层之上再叠弹层。解法：层次只服务于内容分组；能用间距分开的不用边框，能用边框分开的不再加阴影。

## 改稿时的处理顺序

先删自我说明、平安播报和多余的说明小字，再统一提交模型和入口行为，然后处理信号堆叠与撞色，最后调整精度与占位符。每一步都不改变数据语义和已确认的产品规则；涉及功能边界的删除，先在文档中确认边界已有交代。
