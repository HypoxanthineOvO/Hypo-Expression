# README与首页介绍

## 理解内容与读者

先阅读仓库中与介绍相关的资料，理解它提供什么、由什么需求产生、读者怎样开始使用。已有README可能不完整，应结合实际文件和已确认的维护者说明补充理解。不同类型的仓库需要不同栏目，不强制每份README都有安装、API、性能或部署章节。

## 先完成介绍，再展开用法

开头明确介绍对象及用途。随后根据需要解释开发缘由、读者面临的问题和内容如何回应这些问题。让读者能判断与自己的需求是否相关，再安排开始使用所需的信息。

问题描述取自真实需求，不把可能的困难写成所有人都经历过的事实，不夸大影响，也不虚构低水平的其他做法来衬托优势。介绍有明确的重点和作者判断，不用内部检查、规则数量或目录清单替代对内容本身的说明。

展示结构、功能或组成时，解释它们与用途的联系。根据实际内容采用段落、列表、表格、图或示例，不要求统一的功能卡片格式。示例应帮助读者理解用法或差异，并且有足够上下文；没有可公开的真实例子时，可以明确使用自拟情境。

## 使用信息与进一步阅读

给出适合本仓库的最短可用路径，以及必要的获取方式、条件和入口。较长教程或细节可链接到配套文档，首页仍要保留足以理解对象的介绍。维护者要求保留的内容和原有有效信息不因重写而省略。

版本和许可证等标记可以放在标题附近，内容和链接与实际发布一致。说明测试对象时区分针对哪些对象调整过、哪些对象实际试过，以及哪些只是能够读取或使用，避免混淆；明确的后续计划可简要交代。

贡献、引用、许可及其他栏目按实际需要组织。以开发者或内容本身介绍，不机械在每段添加“开发者认为”。检查标题、开头与后文是否呈现一致的定位，链接和命令是否对应当前说明的版本。
