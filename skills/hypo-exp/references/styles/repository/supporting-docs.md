# 配套文档

根据读者任务选择组织方式，既有格式和维护者要求优先。以下是常见用途，不要求每个仓库都有全部文档。

## 教程与操作指南

教程帮助读者完成一次连贯的学习或实践，从必要背景开始，按理解与操作顺序展开。操作指南围绕具体任务，交代前提、步骤和结果。实际需要哪一种，由用户目的决定。

步骤之间的输入和输出应衔接，读者需要作选择时解释选择依据。命令、路径、字段及预期结果来自实际材料；没有运行过的步骤不能写成已验证。不要将作者内部的排查记录全部转成使用者必须执行的步骤。

## 设计与原理说明

围绕需要理解的问题组织：哪些要求影响设计，各部分如何配合，关键选择为何成立，会带来什么结果。技术细节用于解释关系，不将目录或组件清单当作完整设计说明。

涉及取舍时说明真实背景与考虑，不虚构曾被放弃的方案。历史实现只在帮助理解当前设计时展开，避免将探索过程逐条搬入正文。

## 参考资料

围绕读者查找的对象组织信息，名称、定义、字段、条件与关联入口应稳定且可定位。根据内容选用表格、分节和交叉链接。说明以准确、完整和便于查找为目标，不因追求叙事连贯而撤掉有用的结构。

同一内容在不同文档中出现时，保持定义与事实一致，必要时链接到主要说明处。用户明确要求某份文档自包含时，在该文档提供完成理解或操作所需的信息。
