# 查证与作者裁决

用于沟通、写作和改稿中影响理解或准确性的信息缺口。润色不等于只处理已给出的文字：用户未逐一列出文件时，也应在可访问的项目范围内主动寻找相关材料。项目之外的事实需要查证时，按任务范围查阅可靠来源。

## 先查已有信息

围绕待写内容或具体疑点阅读：

- 当前稿与必要的前后章节，理解本段承接什么、要说明什么、后文如何使用其结果。
- 项目概览、研究目标、术语定义和作者已确认的写作意图。
- 对应的实验设计、配置、结果、图表及解释数据的现有记录；需要弄清实现含义时再定位相关代码。
- 已有批注、讨论、改稿记录和历史决定；根据版本关系判断哪些仍然有效。

先定位相关资料，再沿引用和问题追踪。读到一份说明不等于已经理解全部项目，也不要求为每次改句遍历整个仓库。能从现有材料确定的内容直接处理，无需再次让用户提供或重复确认。

## 将已查明的信息用于修改

查阅是为了把内容理解准确，并落实到表达中。能够由资料确定的事实直接使用；有充分依据的错误应纠正，原文缺少的必要背景、定义或衔接可以在编辑范围内补足。不能因为用户说“润色”就拒绝查阅或保留已查明的错误。

涉及核心结论、作者立场或存在冲突的研究解释时，先带依据与用户讨论。对数字、条件或结论的实质纠正，在交付说明中简要指出，便于作者了解变化；不把查证过程逐项塞入正文。

## 把尚未解决的问题交给作者

查阅后仍存在影响含义的冲突、缺失或作者取舍时，在对话中集中提出必要问题。每个问题应让用户看见：

1. 哪句话或哪项判断需要决定。
2. 已经读了哪些相关材料、分别得到什么信息，给出简短定位。
3. 具体还存在什么差别，影响哪一种写法或论证。
4. 需要作者确认的事实、意图或选择；有依据时说明自己的建议。

不要只问“请提供更多背景”，也不要把一串文件路径当成阅读证明。依据应与问题直接对应；项目中已有明确答案时继续查阅和处理。

## 正文与讨论分开

模型暂时没看懂、尚未找到资料或不能决定的状态，不是研究本身的结论。不要把它写成论文中的“无法确定”“尚不能证明”“材料没有说明”等声明，也不要借此弱化作者原有主张。

尚待裁决的句子暂留待处理，在对话中指出，不擅自把猜测写进正文或将其当作完成稿交付。可以继续修改已确定且不依赖该问题的部分。作者裁决后，将相应事实、条件和解释正常写入正文，保留原有信息量。

研究本身已有的结果、真实条件和作者确认需要呈现的限制，按正常论述表达；作者裁决不能替代不存在的实验事实。

## 固定样本测试

用户明确要求只依据给定样本进行测试时，遵守该材料范围，不读取项目、历史批评、后期稿或其他模型输出。需要测试项目阅读能力时，另开允许读项目的测试，并明确提供材料范围。不能在一次固定输入测试中途补入额外上下文，再把变化全部归因于措辞规则。
