# 查证与作者裁决

用于沟通、写作和改稿中影响理解或准确性的信息缺口。润色同样需要查证：用户没有逐一列出文件时，也在可访问的项目范围内主动寻找相关材料；项目之外的事实，按任务范围查阅可靠来源。

## 先查已有信息

围绕待写内容或具体疑点阅读：

- 当前稿和必要的前后章节：本段承接什么、要说明什么、后文如何使用它的结果。
- 项目概览、研究目标、术语定义和作者已确认的写作意图。
- 对应的实验设计、配置、结果、图表和解释数据的记录；需要弄清实现含义时再看相关代码。
- 已有批注、讨论、改稿记录和历史决定，并根据版本关系判断哪些仍然有效。

先定位相关资料，再沿着引用和问题往下追。每次改句不必遍历整个仓库，但读到一份说明也不代表已经理解了项目。能从现有材料确定的内容直接处理，不再让用户提供或确认。

## 用查到的信息修改

能由资料确定的事实直接使用；有充分依据的错误予以纠正；原文缺少的定义、背景或衔接，在编辑范围内补足。涉及核心结论、作者立场或存在冲突的研究解释，先带着依据与用户讨论。对数字、条件或结论的实质纠正，在交付说明里简要指出，查证过程本身不写进正文。

## 把尚未解决的问题交给作者

查阅后仍有影响含义的冲突、缺失或取舍，在对话中集中提出。每个问题说明：

1. 哪句话或哪项判断需要决定。
2. 读了哪些相关材料，各自得到什么信息，附简短定位。
3. 还存在什么差别，会影响哪种写法或论证。
4. 需要作者确认的事实、意图或选择；有依据时给出自己的建议。

问题要具体，依据要与问题直接对应。“请提供更多背景”或一串文件路径都帮不了作者做决定。

## 正文与讨论分开

模型暂时没看懂、没找到资料或不能决定的状态，不是研究本身的结论，不写成正文里的“无法确定”“尚不能证明”“材料没有说明”，也不借此削弱作者的主张。待裁决的句子暂时保留原样，在对话中指出；不依赖该问题的部分照常修改。作者裁决后，把相应事实、条件和解释正常写入正文。

研究本身的结果、真实条件和作者确认要呈现的限制，按正常论述表达。

## 固定样本测试

用户要求只依据给定样本测试时，遵守该材料范围，不读取项目、历史批评、后期稿或其他模型的输出。测试项目阅读能力需另开测试，并明确材料范围。同一次测试中途不补入额外上下文，以免把变化全部归因于表达规则。
